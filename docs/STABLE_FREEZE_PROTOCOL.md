# ❄️ ПРОТОКОЛ СТАБІЛІЗАЦІЇ ТА ЗАМОРОЗКИ (STABLE_FREEZE_PROTOCOL)

Цей протокол застосовується, коли фіча або модуль вважається завершеним і має бути захищеним від регресій.

## 1. Критерії "заморозки"
- Функціональність повністю реалізована згідно з `TASK_TEMPLATE.md`.
- Немає відкритих багів рівня High/Critical.
- Дизайн відповідає `UI_SPEC_TEMPLATE.md`.
- Провідні розробники/користувач підтвердили роботу.

## 2. Обмеження після заморозки
- **Жодних ламаючих змін (Breaking Changes):** Заборонено змінювати сигнатури функцій або схеми БД без крайньої необхідності.
- **Мінімальні правки:** Дозволено лише багфікси або додавання нових полів (incremental changes).
- **Збереження зворотної сумісності:** Новий код не повинен ламати те, що вже працює.

## 3. Процес внесення змін у "заморожений" код
- Будь-яка зміна має бути аргументована.
- Обов'язкове тестування всього модуля після внесення змін (Full Regression Testing).
- Якщо зміна вимагає порушення `AGENT_RULES.md`, вона має бути окремо погоджена з користувачем.

## 4. Вихід зі стану заморозки
- Модуль може бути розморожений для масштабного рефакторингу або додавання великої нової фічі після створення нового плану розробки та схвалення його користувачем.
