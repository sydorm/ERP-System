# Журнал критичних помилок (Не повторювати!)

Цей файл створено за вимогою користувача для фіксації важливих помилок, які часто повторюються, щоб AI вчився на них і не допускав їх у майбутньому.

## 1. Помилки міграцій Alembic (Vultr)
**Симптоми:** Під час оновлення `./scripts/update.sh` падає з `DuplicateTable`, `DuplicateColumn`, `DuplicateObject` або `KeyError`.
**Причина:** Міграції SQLAlchemy намагалися створити колонки/таблиці, які вже існують в продакшені через частково злиті гілки або попередні збої. `KeyError` виникав через наявність паралельних гілок (`down_revision`), яких немає в базі сервера.
**Рішення (ОБОВ'ЯЗКОВО ДО ВИКОНАННЯ):**
Усі нові файли міграцій (`alembic/versions/*.py`) **повинні бути ідемпотентними**.
- Використовуйте `sa.inspect(op.get_bind())` для перевірки наявності таблиць/колонок перед `op.add_column` або `op.create_table`.
- НІКОЛИ не використовуйте `try/except` для приховування помилок схем, використовуйте явні перевірки `if 'column_name' not in existing_columns:`.

## 2. Помилка 500 (Internal Server Error) при завантаженні товарів
**Симптоми:** Фронтенд не показує дані, бекенд видає 500.
**Причина:** Локальний код бекенду (моделі Pydantic/SQLAlchemy) очікує нові колонки (наприклад, `length_cm`, `weight_kg`), але міграція БД на сервері Vultr ще не пройшла (або впала з помилкою з пункту 1).
**Рішення:** Завжди перевіряти статус міграцій (`docker-compose exec backend alembic current`) та успішність виконання `update.sh` на сервері. Якщо є 500 помилка після деплою — у 99% випадків це розсинхрон БД.

## 3. Відсутність прав доступу (Permission Denied) для .sh скриптів
**Симптоми:** Bash: `./scripts/update.sh: Permission denied`
**Рішення:** Скрипти втрачають права на виконання при `git pull`. Завжди нагадувати користувачу виконувати `chmod +x scripts/update.sh` на сервері.

## 4. Дві кнопки "Зберегти" (Поганий UX)
**Симптоми:** Користувач створює специфікацію на вкладці, але забуває натиснути форму збереження перед використанням розумного калькулятора.
**Рішення:** Не розбивати пов'язані сутності по різних вкладках (наприклад, Специфікації та Розумна Специфікація). Калькулятори та налаштування мають бути вбудовані прямо в таблицю BOM (через діалогові вікна), щоб користувач не втрачав контекст.
