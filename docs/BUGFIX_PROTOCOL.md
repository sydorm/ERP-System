# 🐛 ПРОТОКОЛ ВИПРАВЛЕННЯ ПОМИЛОК (BUGFIX_PROTOCOL)

Цей протокол описує кроки, які необхідно виконати при виявленні помилок (зокрема 500 Internal Server Error).

## 1. Аналіз та Дослідження
- **Перегляд логів:** Перевірити логи бекенду (Docker/Terminal) для отримання повної інформації про помилку (Traceback).
- **Локалізація:** Визначити, який файл та рядок коду викликають помилку.
- **Відтворення:** Описати кроки для відтворення помилки.

## 2. Створення Плану Виправлення
- Перед внесенням змін створити короткий план у чаті.
- Пояснити причину помилки та запропоноване рішення.
- Перевірити, чи не порушує виправлення `AGENT_RULES.md` (наприклад, видалення колонок БД).

## 3. Виправлення
- Внести мінімально необхідні зміни для усунення помилки.
- Якщо помилка пов'язана зі схемою бази даних — створити нову міграцію Alembic (не змінювати старі міграції!).
- Якщо помилка на фронтенді — забезпечити обробку помилок (try/catch) та вивід зрозумілих повідомлень користувачу.

## 4. Верифікація
- Перевірити виправлення в браузері.
- Переконатися, що функціональність працює як очікується.
- Перевірити, чи не виникли регресії (чи не зламалося щось інше).

## 5. Документування
- Оновити `walkthrough.md` після успішного виправлення.
- Якщо помилка була критичною — додати опис у розділ "Known Issues" (якщо є).
