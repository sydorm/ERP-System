# 🧠 ГЛОБАЛЬНІ ПРАВИЛА ДЛЯ АГЕНТІВ (AGENT_RULES)

Ці правила є обов'язковими для виконання всіма ШІ-агентами, що працюють над цим проєктом.

## 🛑 1. НІЧОГО НЕ ВИДАЛЯЙ БЕЗ ДОЗВОЛУ
- Заборонено видаляти будь-який існуючий файл, функцію, клас, змінну, CSS-клас, ID, рядок коду.
- Заборонено перейменовувати файли, компоненти, функції, класи, змінні, CSS-класи, ID.
- Заборонено переписувати існуючий код «з нуля».
- Якщо вважаєш, щось треба видалити/змінити — **ОБОВ’ЯЗКОВО запитай користувача в чаті**. Чекай відповіді.

## ✅ 2. ЩО МОЖНА РОБИТИ БЕЗ ПИТАННЯ
- Додавати нові файли, функції, компоненти, стилі.
- Розширювати існуючий код (нові поля, методи, кнопки), не чіпаючи старе.
- Виправляти очевидні синтаксичні помилки, якщо це не змінює логіку.

## 🎯 3. ІНКРЕМЕНТАЛЬНІ ЗМІНИ — НЕ ПЕРЕПИСУЙ ТЕ, ЩО ПРАЦЮЄ
- **НЕ МОЖНА:** видаляти сторінку/компонент і писати «з нуля» без команди.
- **НЕ МОЖНА:** повністю змінювати структуру HTML/CSS без дозволу.
- **ТРЕБА:** додавати нове поряд зі старим.
- **ТРЕБА:** використовувати Feature Flags (прапорці функцій) для приховування/показу нового коду.
- **ТРЕБА:** один запит — одна логічна зміна.

## 🤔 4. ПРАВИЛО ГНУЧКОСТІ
- Ти маєш право запропонувати порушення правил, якщо це об'єктивно покращить код.
- **Порушення можливе ТІЛЬКИ після прямого підтвердження користувачем.**

## 🎨 5. СТИЛЬ ТА АДАПТИВНІСТЬ
- Усі сторінки мають коректно відображатися на мобільних пристроях (≤640px).
- Використовуй Flex/Grid, уникай фіксованої ширини.
- Кнопки на мобільному — на всю ширину.
- Дотримуйся існуючої кольорової гами та відступів у проєкті.

## 🗄️ 6. РОБОТА З БАЗОЮ ДАНИХ
- Нові поля — обов’язково `nullable=True` або `default`.
- Ніколи не видаляй колонки, які вже використовуються.
- Індекси — на всі зовнішні ключі.
- Міграції Alembic — окремий файл на кожну зміну.

## 💬 7. КОМУНІКАЦІЯ
- Перед виконанням складного завдання запропонуй план (Implementation Plan).
- Показуй результат у браузері після кожної зміни.
- Якщо зробив помилку — визнай і запропонуй виправлення.
